## 2. Основные принципы

1. **Документация — тоже код.**  
   Все изменения в `food-delivery-docs` делаются через Pull Request и проходят ревью.

2. **Единый источник истины.**  
   Не дублируем одну и ту же информацию в нескольких местах. Если информация изменилась — обновляем первоисточник.

3. **Актуальность важнее красоты.**  
   Устаревшая документация хуже, чем её отсутствие. При изменении поведения системы документация обновляется в том же PR (или сразу после).

4. **Пишем для будущего себя и новых людей.**  
   Через 6–12 месяцев документ должен быть понятен человеку, который не участвовал в принятии решения.

## 3. Как обновлять документы в этом репозитории

1. Создаётся ветка от `main` (или `dev`, когда появится).
2. Вносятся изменения.
3. Открывается Pull Request.
4. Минимум один approve.
5. Merge.

Для небольших правок (опечатки, уточнения формулировок) допускается прямой коммит в `main` на этапе Sprint 0. После перехода в регулярную разработку — только через PR.

## 4. Именование и структура

- ADR: `ADR-XXX-краткое-название.md`
- Процессные документы — в папке `process/`
- Шаблоны — в папке `templates/`
- Язык документов: **русский** (основной), технические термины и названия технологий — на английском.

## 5. Кто за что отвечает

- **Tech Lead** — актуальность PROJECT_CONTEXT, ADR, DoR, DoD, структуры репозитория.
- **Команда** — актуальность документации внутри своих сервисов.
- **Product Owner** — актуальность описаний в Confluence.
