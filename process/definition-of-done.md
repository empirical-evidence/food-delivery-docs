# Definition of Done (DoD)

**Статус документа:** Approved  
**Версия:** 1.0  
**Дата:** 2026-09-05  
**Владелец:** Tech Lead  
**Область применения:** все User Stories, задачи и Pull Request'ы в проекте Food Delivery Platform

## Назначение

Definition of Done определяет, когда работа считается **полностью завершённой** и может быть принята.

Задача не считается Done, пока не выполнены все критерии ниже.

## Критерии Definition of Done

### 1. Реализация
- [ ] Код написан и соответствует принятым code style и naming conventions
- [ ] Реализованы все Acceptance Criteria
- [ ] Учтены non-functional requirements (если были указаны)
- [ ] Нет закомментированного или отладочного кода
- [ ] Нет хардкода секретов, паролей, URL окружений

### 2. Тестирование
- [ ] Написаны unit-тесты на ключевую бизнес-логику
- [ ] Написаны интеграционные тесты (если задача затрагивает взаимодействие с БД, Kafka, другими сервисами)
- [ ] Все тесты проходят успешно в CI
- [ ] Покрытие тестами соответствует договорённостям команды (минимум — критичные пути)
- [ ] Проведено ручное тестирование happy path и основных негативных сценариев

### 3. Качество кода и ревью
- [ ] Создан Pull Request в ветку `dev`
- [ ] Проведён Code Review минимум одним другим разработчиком
- [ ] Все замечания ревьюера исправлены или обсуждены
- [ ] PR получил approve
- [ ] Нет критичных замечаний от статического анализа (если настроен)

### 4. Документация и контракты
- [ ] Если менялся API — обновлена OpenAPI-спецификация
- [ ] Если менялась схема БД — добавлена миграция Flyway
- [ ] Если принималось архитектурное решение — создан или обновлён ADR
- [ ] Обновлена необходимая документация в Confluence / этом репозитории
- [ ] README сервиса актуален (если изменения его затрагивают)

### 5. Интеграция и окружения
- [ ] Изменения успешно собраны и прошли тесты в CI
- [ ] Код влит в ветку `dev`
- [ ] Сервис корректно работает в локальном окружении (docker-compose)
- [ ] Нет Breaking Changes без предварительного согласования и версионирования

### 6. Завершение задачи
- [ ] Все подзадачи (Sub-tasks) закрыты
- [ ] В Jira у задачи проставлен статус Done
- [ ] В комментарии к задаче (или в PR) кратко описано, что сделано
- [ ] Product Owner / ответственный принял результат (если требуется демонстрация)

## Дополнительные правила

- **Hotfix** в `prod` допускается только при критичных инцидентах и проходит упрощённый, но обязательный Code Review.
- Любое отклонение от DoD должно быть явно согласовано с Tech Lead и зафиксировано.
