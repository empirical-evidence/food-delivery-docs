# ADR-006: Java 21 + Spring Boot 3.x

**Статус:** Accepted  
**Дата:** 2026-09-05  
**Автор:** Tech Lead  

## Контекст

Необходимо зафиксировать базовый язык и фреймворк для всех сервисов Food Delivery Platform.

Требования:
- Современный LTS-релиз Java
- Актуальная версия Spring Boot с долгосрочной поддержкой
- Хорошая поддержка виртуальных потоков, улучшенной производительности и современных языковых конструкций
- Совместимость с Spring Cloud, OpenFeign, Kafka, PostgreSQL и остальным выбранным стеком
- Единообразие всех сервисов

## Решение

В качестве базового стека принимается:

- **Java 21** (LTS)
- **Spring Boot 3.x** (актуальная стабильная линейка 3.x)
- **Spring Cloud** (соответствующая версия, совместимая с выбранной Spring Boot)

Все сервисы создаются и поддерживаются на этом стеке.  
Отклонения допускаются только по согласованию с Tech Lead и с отдельным ADR.

## Альтернативы

### 1. Java 17 + Spring Boot 3.x
Java 17 тоже LTS и полностью поддерживается.  
Однако Java 21 даёт виртуальные потоки (Project Loom), улучшенный GC, pattern matching и другие возможности, которые уже достаточно зрелы для продакшена.

### 2. Java 21 + Spring Boot 2.x
Невозможно: Spring Boot 2.x не поддерживает Java 21 и основан на javax.* вместо jakarta.*.

### 3. Другие фреймворки (Quarkus, Micronaut, pure Jakarta EE)
Отклонены на текущем этапе: команда имеет наибольшую экспертизу именно в Spring-экосистеме, а скорость разработки и зрелость интеграций имеют высокий приоритет.

## Последствия

### Положительные
- Современный язык с виртуальными потоками
- Актуальная и активно развивающаяся экосистема Spring
- Единый стек для всех сервисов → проще onboarding, шаблоны, code review
- Хорошая поддержка observability, security, data access, messaging

### Отрицательные
- Нужно следить за совместимостью версий Spring Boot и Spring Cloud
- Некоторые старые библиотеки могут ещё не поддерживать Jakarta EE namespace
- Команда должна освоить особенности Java 21 (особенно виртуальные потоки — использовать осознанно)

### Компенсирующие меры
- Единый шаблон сервисного репозитория с зафиксированными версиями
- Регулярное обновление зависимостей через Pull Request’ы
- Документирование используемых возможностей Java 21, которые мы принимаем как стандарт
